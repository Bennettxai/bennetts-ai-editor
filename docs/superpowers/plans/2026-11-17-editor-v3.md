# AI Video Editor v3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Use test-first changes and independent review.

**Goal:** Ship an unbranded local editor with portable dialogue editing, reliable 4K/source-rate output, versioned cut integrity, diagnostics and CI.

**Architecture:** Extend the current JSON-timeline Node/Remotion application. Introduce shared format/timing helpers and isolated dialogue receipt functions, then integrate them into the existing CLI. Preserve legacy projects and local-only media processing.

**Tech Stack:** Node >=22, JavaScript/TypeScript, pinned Remotion 4.0.536, React 18, FFmpeg/ffprobe, optional whisper.cpp.

**Spec:** `docs/superpowers/specs/2026-11-17-editor-v3-design.md`

## Global Constraints

- New projects: 2160×3840 final, 540×960 drafts, source frame rate including fractional rates; legacy projects: 1080×1920 at 30fps.
- Final H.264 CRF <=10; no low-resolution intermediate; audio mastering copies video.
- No personal branding or private resources; preserve legal attribution and repository address.
- Never overwrite original footage; no external uploads or social publishing.
- Automated checks cannot certify listening, take quality or creator approval.
- Preserve the original checkout's dirty branding files. Work only in the isolated release checkout.

## Review Focus

- Fractional frame boundaries and late audio starts: captions, footage and exact frame counts must share the same clock (Task 1).
- VFR or unsupported input rates: explicit normalization/diagnostics rather than a false native-frame claim (Task 1).
- Valid-looking old captions/graphics after a cut: dependency invalidation must detect these too (Task 2).
- Source/transcript/proposal replacement between review and apply: refuse before changing edits or receipts (Task 2).
- Missing transcription dependencies and legacy media: truthful readiness and actionable status without blocking supported import workflows (Task 3).

### Task 1: Native timing and 4K media workflow

**Files:** new `src/format.mjs` and declarations; `src/edit.mjs`, `src/captions.mjs`, `src/cuts.mjs`, `src/Root.tsx`, `src/layout.mjs`, `src/scenes/*`, `scripts/editor.mjs`, `scripts/review.mjs`; relevant tests and a new format/media integration test.

**Interfaces:** expose `getFormat(edit)` returning numeric `fps`, rational `fpsRatio`, final `width/height`, and `scale` from `edit.format`. `edit.format` uses `{fps: '30000/1001', resolution: '4k'|'1080p'}`; missing format returns legacy 30/1 and 1080p. Other internal names may be chosen consistently. Extend timeline helpers with an optional fps argument while preserving old callers. Record source probe metadata in the project.

### Task 2: Reviewed dialogue cuts, revisions and stale-data protection

**Files:** new `src/dialogue.mjs`; `scripts/editor.mjs`, `src/cuts.mjs` as needed; new dialogue tests plus CLI integration tests.

**Interfaces:** use Task 1 `getFormat(edit)` for the source/output frame clock. Keep `cut` as the proposal/apply command, adding `--plan <json>` and explicit `--clear-overlays` for a changed cut with dependent graphics/SFX. Add `dialogue` for revision/status/review inspection. Keep a current revision pointer and versioned `vNNN` receipts in each project. `dialogue --snapshot` explicitly adopts a manually edited timeline or corrected transcript into a new revision; it must archive old state, invalidate dependent output timings when cuts change, and reset human review gates rather than silently approve them. `dialogue --review <json>` records explicit reviewer evidence, with separate technical/takeSelection/cutCoverage/listening states. Rendering may create a preview for listening with pending human gates, but status/review must expose them and the skill must not call it a fully reviewed delivery.

- [ ] Write failing tests that prove `--apply --plan` uses reviewed selections, rejects changed source/transcript/base clips and invalid ranges before mutation, and records exact contiguous frame mappings.
- [ ] Write failing tests for stale overlays that remain in bounds, source/transcript changes after a revision, explicit overlay clearing with archived recovery data, and pending listening/review gates.
- [ ] Implement versioned atomic revision creation and dependency checks. Default apply must require and use the saved proposal; if absent, fail with the proposal-generation command. The plan must identify source SHA256, transcript SHA256, base clip clock hash and frame rate. Old anonymous/manual plan JSON must not bypass these identity checks. Validate full-word preservation or require explicit per-range reviewed exceptions. Never infer semantic/listening passes.
- [ ] Integrate cut/caption/words/render paths so output-clock artifacts are bound to the current cut and changes cannot silently produce a stale render. Document manual-edit recovery with actionable commands.
- [ ] Run full tests/typecheck and a real generated-media dialogue workflow; commit and report.
